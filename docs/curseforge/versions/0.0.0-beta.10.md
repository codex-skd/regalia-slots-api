<h2>v0.0.0-beta.10 - equip_curio slot filter now applies</h2>

<p>Tenth beta of Regalia Slots API for <strong>Minecraft 1.21.1 / NeoForge 21.1.249</strong> (Java 21). Closes the caveat left open in beta.9.</p>

<h3>Fixed</h3>
<ul>
<li><strong>Slot filter on the <code>equip_curio</code> trigger was ignored for Curios-native criteria</strong>: the slot sub-predicate codec keyed on <code>regalia_slots_api:slot</code>, so an advancement written for Curios (e.g. Iron's Spellbooks' <code>spell_book_equip</code>, which filters on the <code>spellbook</code> slot) loaded but matched <em>any</em> Regalia-slot equip. Renamed the field to <code>curios:slot</code> in <code>EquipCurioTrigger.TriggerInstance.CODEC</code>; it is the only advancement-criterion consumer of that key, so this is a clean move to full Curios parity.</li>
</ul>

<h3>Notes</h3>
<blockquote>Regalia Slots API is a library. It adds no content on its own — install it only as a dependency of another mod that requires it, on both client and server. <strong>Incompatible with the real Curios mod</strong> (shared <code>curios</code> mod id); install one or the other. LGPL-3.0-or-later; the full licence text ships in the jar.</blockquote>

<h2>v0.0.0-beta.11 - Fix load crash from duplicate trigger registration</h2>

<p>Eleventh beta of Regalia Slots API for <strong>Minecraft 1.21.1 / NeoForge 21.1.249</strong> (Java 21). <strong>beta.9 and beta.10 crash on load</strong> in any pack that reaches the <code>curios:equip_curio</code> trigger without a datapack override; every user of those builds should update.</p>

<h3>Fixed</h3>
<ul>
<li><strong>Crash during mod loading</strong> (<code>IllegalStateException: Adding duplicate value '…EquipCurioTrigger@…' to registry</code>, from <code>MappedRegistry.register</code> in <code>RegisterEvent</code>). beta.9 registered <code>curios:equip_curio</code> with the same <code>EquipCurioTrigger</code> object already registered as <code>regalia_slots_api:equip_curio</code>. Vanilla <code>MappedRegistry</code> dedupes by value identity and rejects the second key, aborting the whole mod-loading phase.</li>
</ul>

<h3>Technical</h3>
<ul>
<li><code>EquipCurioTrigger</code> now has two instances — <code>INSTANCE</code> (<code>regalia_slots_api:equip_curio</code>) and <code>CURIOS_COMPAT_INSTANCE</code> (<code>curios:equip_curio</code>).</li>
<li>Runtime triggers fan out through a private <code>fire(...)</code> that notifies the advancement listeners of <strong>both</strong> instances, so criteria authored under either id still fire on a curio equip. No behaviour change for <code>regalia_slots_api:equip_curio</code> advancements; <code>curios:equip_curio</code> advancements now both load (beta.9) and trigger (this release).</li>
</ul>

<h3>Notes</h3>
<blockquote>Regalia Slots API is a library. It adds no content on its own — install it only as a dependency of another mod that requires it, on both client and server. <strong>Incompatible with the real Curios mod</strong> (shared <code>curios</code> mod id); install one or the other. LGPL-3.0-or-later; the full licence text ships in the jar.</blockquote>

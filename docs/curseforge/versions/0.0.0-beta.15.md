<h2>v0.0.0-beta.15 - Third-party curio rendering</h2>

<p>Bug-fix beta for <strong>Minecraft 1.21.1 / NeoForge 21.1.249</strong> (Java 21).</p>

<h3>Fixed</h3>
<ul>
<li><strong>Curios items from other mods rendered as nothing on the player.</strong> The bundled
Curios compatibility layer bridged capabilities, slot types, predicates and attribute modifiers,
but not the client renderer registry. Mods such as Relics register their curio models through
<code>top.theillusivec4.curios.api.client.CuriosRendererRegistry</code> &mdash; a verbatim copy of
the Curios class whose maps nothing ever read (<code>load()</code> was never called, and the
render layer only queried Regalia's own registry). The item equipped and applied its effects, but
was invisible on the body (for example Relics' <code>amphibian_boot</code>). Third-party curio
renderers are now forwarded into Regalia's render layer.</li>
</ul>

<h3>Technical</h3>
<ul>
<li>New <code>com.skd.regaliaslotsapi.compat.curios.CuriosRendererAdapter</code> adapts between the
two identical-but-separate <code>ICurioRenderer</code> / <code>SlotContext</code> type hierarchies
(<code>top.theillusivec4.curios.api.*</code> &harr; <code>com.skd.regaliaslotsapi.api.*</code>).
Anonymous classes rather than lambdas, because <code>ICurioRenderer#render</code> is generic.</li>
<li><code>CuriosRendererRegistry#register</code> now forwards every registration to
<code>RegaliaSlotsApiRendererRegistry</code> through the adapter. The existing
<code>RegaliaSlotsApiRendererRegistry.load()</code> call in
<code>EntityRenderersEvent.AddLayers</code> materialises them &mdash; no second listener is added,
and there is no behaviour change for renderers registered directly into Regalia's registry.</li>
</ul>

<h3>Notes</h3>
<blockquote>Library / API mod (Curios API fork), no gameplay change. <strong>Incompatible with the
real Curios mod</strong> (shared <code>curios</code> mod id); install one or the other. Verified:
<code>./gradlew clean build</code> is green. Rendering not yet verified in-game.
LGPL-3.0-or-later; the full licence text ships in the jar.</blockquote>

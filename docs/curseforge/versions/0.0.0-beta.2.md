<h2>v0.0.0-beta.2 - Curios API Compatibility Fix</h2>

<p>Second beta of Regalia Slots API for <strong>Minecraft 1.21.1 / NeoForge 21.1.249</strong> (Java 21).</p>

<h3>Fixed</h3>
<ul>
<li><strong>Curios API compatibility</strong>: Added mixin implementation for <code>top.theillusivec4.curios.api.CuriosApi</code> so other mods (Ars Nouveau, etc.) can properly access Curios inventory capabilities without spamming "Missing Curios API implementation!" errors in server logs.</li>
<li>Other mods using <code>CuriosApi.getCuriosInventory()</code>, <code>CuriosApi.getCurio()</code>, <code>CuriosApi.getSlots()</code>, etc. now work correctly with Regalia Slots API as the Curios provider.</li>
</ul>

<h3>Technical</h3>
<ul>
<li>New mixin <code>MixinCuriosApi</code> targeting <code>top.theillusivec4.curios.api.CuriosApi</code> with adapter methods bridging Regalia's internal API to the Curios API types.</li>
<li>Adapter methods in <code>RegaliaSlotsApiImplMixinHooks</code> for slot types, capabilities, predicates, and slot contexts.</li>
<li>Made <code>ShimSlotType</code> constructor public for cross-package usage.</li>
</ul>

<h3>Notes</h3>
<blockquote>Regalia Slots API is a library. It adds no content on its own &mdash; install it only as a dependency of another mod that requires it, on both client and server. <strong>Incompatible with the real Curios mod</strong> (shared <code>curios</code> mod id); install one or the other. LGPL-3.0-or-later; the full licence text ships in the jar.</blockquote>

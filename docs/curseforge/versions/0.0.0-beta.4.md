<h2>v0.0.0-beta.4 - Curios API compatibility layer</h2>

<h3>Added</h3>
<ul>
<li><strong>Curios API compatibility layer</strong>: third-party mods that hard-depend on the real Curios mod id (<code>curios</code>) and its <code>top.theillusivec4.curios.api.*</code> package (e.g. Sophisticated Backpacks) now recognize and interact with Regalia Slots API's own slots, without requiring the user to install Curios itself.</li>
<li>A second logical mod (<code>modId="curios"</code>) is declared in this same jar, with its own capabilities (<code>curios:inventory</code>, <code>curios:item</code>) backed live by Regalia Slots API's real inventory data - nothing is duplicated between the two mod ids.</li>
</ul>

<h3>Known limitations</h3>
<ul>
<li>Per-item custom curio behavior (equip sounds, glow effects, custom tooltips) declared through <code>ICurioItem</code>/<code>ICurio</code> is not yet bridged - items still get slot recognition and full inventory read/write access, but fall back to default behavior instead of a mod's custom overrides.</li>
<li>Rendering equipped items as models on the entity via Curios' own client-side renderer registry is not connected yet.</li>
<li><strong>Installing the real Curios mod alongside this one is not supported</strong>: NeoForge will fail to load due to the duplicate <code>curios</code> mod id. This is intentional - remove one before adding the other.</li>
</ul>

<blockquote>If you rely on a Curios-integrated mod beyond basic slot placement and inventory access, please report what's missing so it can be prioritized.</blockquote>

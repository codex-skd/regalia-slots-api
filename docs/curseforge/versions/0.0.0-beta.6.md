<h2>v0.0.0-beta.6 - Legacy Curios helper compatibility</h2>

<p>Sixth beta of Regalia Slots API for <strong>Minecraft 1.21.1 / NeoForge 21.1.249</strong> (Java 21).</p>

<h3>Fixed</h3>
<ul>
<li><strong>Legacy <code>CuriosApi.getCuriosHelper()</code> returned <code>null</code></strong>: mods that still use the deprecated Curios helper accessor &mdash; Supplementaries (quiver), L_Ender's Cataclysm (first-person arm rendering) and others &mdash; crashed with a <code>NullPointerException</code>. The compat layer bridged the modern <code>CuriosApi</code> static methods but never wired <code>getCuriosHelper()</code>, so every caller hit a null helper (server "Ticking player" crash and client render FATAL). <code>getCuriosHelper()</code> now returns a shim <code>ICuriosHelper</code> backed by the same compatibility layer.</li>
</ul>

<h3>Technical</h3>
<ul>
<li>New <code>com.skd.regaliaslotsapi.compat.curios.LegacyCuriosHelperShim</code> implementing <code>top.theillusivec4.curios.api.type.util.ICuriosHelper</code>, delegating to <code>CuriosImplMixinHooks</code>: <code>getCurio</code> / <code>getCuriosHandler</code> / <code>getCurioTags</code> / <code>isStackValid</code> / <code>onBrokenCurio</code> direct; <code>findCurios*</code> / <code>findFirstCurio*</code> / <code>findCurio</code> / <code>getEquippedCurios</code> / <code>setEquippedCurio</code> / <code>findEquippedCurio</code> resolved through the entity's <code>ICuriosItemHandler</code>.</li>
<li><code>MixinCuriosApi</code> gains a <code>@Inject</code> on <code>getCuriosHelper</code> returning the shim singleton.</li>
</ul>

<h3>Notes</h3>
<blockquote>Regalia Slots API is a library. It adds no content on its own &mdash; install it only as a dependency of another mod that requires it, on both client and server. <strong>Incompatible with the real Curios mod</strong> (shared <code>curios</code> mod id); install one or the other. LGPL-3.0-or-later; the full licence text ships in the jar.</blockquote>

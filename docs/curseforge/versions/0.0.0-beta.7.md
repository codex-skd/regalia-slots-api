<h2>v0.0.0-beta.7 - Curios inventory adapter ClassCastException</h2>

<p>Seventh beta of Regalia Slots API for <strong>Minecraft 1.21.1 / NeoForge 21.1.249</strong> (Java 21).</p>

<h3>Fixed</h3>
<ul>
<li><strong><code>ClassCastException</code> when a mod read the Curios inventory of an entity</strong>: the next link in the same chain as beta.6 &mdash; L_Ender's Cataclysm first-person arm rendering (and any mod calling <code>CuriosApi.getCuriosInventory()</code> / <code>getCurio()</code>) crashed with <code>class com.skd.regaliaslotsapi.common.capability.CurioInventoryCapability cannot be cast to top.theillusivec4.curios.api.type.capability.ICuriosItemHandler</code>. The Curios API adapter methods returned Regalia's internal implementation objects cast straight to the verbatim <code>top.theillusivec4.curios.*</code> interfaces, which those objects never implement. They are now wrapped in forwarding shims, the same pattern already used for slot types (<code>ShimSlotType</code>).</li>
</ul>

<h3>Technical</h3>
<ul>
<li>New shims in <code>com.skd.regaliaslotsapi.compat.curios</code>: <code>ShimCuriosItemHandler</code>, <code>ShimCurio</code>, <code>ShimCurioStacksHandler</code>, <code>ShimDynamicStackHandler</code> &mdash; each implements the verbatim <code>top.theillusivec4.curios.*</code> interface and forwards to the parallel Regalia implementation, wrapping/unwrapping nested capability types and translating <code>SlotContext</code> / <code>SlotResult</code> by value.</li>
<li><code>RegaliaSlotsApiImplMixinHooks.getCurioForCurios</code> / <code>getCuriosInventoryForCurios</code> now return <code>new ShimCurio(...)</code> / <code>new ShimCuriosItemHandler(...)</code> instead of an unchecked cast.</li>
</ul>

<h3>Notes</h3>
<blockquote>Regalia Slots API is a library. It adds no content on its own &mdash; install it only as a dependency of another mod that requires it, on both client and server. <strong>Incompatible with the real Curios mod</strong> (shared <code>curios</code> mod id); install one or the other. LGPL-3.0-or-later; the full licence text ships in the jar.</blockquote>

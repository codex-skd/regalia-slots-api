<h2>v0.0.0-beta.9 - Curios-native advancements now load</h2>

<p>Ninth beta of Regalia Slots API for <strong>Minecraft 1.21.1 / NeoForge 21.1.249</strong> (Java 21).</p>

<h3>Fixed</h3>
<ul>
<li><strong>Advancements from Curios-native mods failed to load</strong>: mods built against the real Curios API hard-code the trigger id <code>curios:equip_curio</code> in their advancement JSON. Iron's Spellbooks does this for <code>spell_book_equip</code> and its 13 tiered child advancements. Regalia only registered the trigger as <code>regalia_slots_api:equip_curio</code>, so those advancements threw <code>Unknown registry key ...:trigger_type: curios:equip_curio</code> and the whole branch was dropped at datapack load.</li>
</ul>

<h3>Technical</h3>
<ul>
<li><code>RegaliaSlotsApiRegistry</code> now also registers the same <code>EquipCurioTrigger.INSTANCE</code> under the <code>curios</code> namespace, via a second <code>DeferredRegister&lt;CriterionTrigger&lt;?&gt;&gt;</code> created with <code>"curios"</code> and wired into the mod event bus in <code>init(...)</code>. <code>curios:equip_curio</code> now resolves.</li>
<li><strong>Caveat</strong>: the trigger's slot sub-predicate codec still keys on <code>regalia_slots_api:slot</code>, so a Curios-native criterion using <code>curios:slot</code> loads but its slot filter is ignored (the advancement fires on any Regalia-slot equip). Restoring that filter is tracked as a follow-up.</li>
</ul>

<h3>Notes</h3>
<blockquote>Regalia Slots API is a library. It adds no content on its own — install it only as a dependency of another mod that requires it, on both client and server. <strong>Incompatible with the real Curios mod</strong> (shared <code>curios</code> mod id); install one or the other. LGPL-3.0-or-later; the full licence text ships in the jar.</blockquote>

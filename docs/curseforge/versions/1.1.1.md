<h2>v1.1.1 - Supersalto II fix for Reliquary's angelic_faher</h2>

<p>The <strong>Supersalto II (Jump Boost II)</strong> effect from Reliquary's <code>angelic_faher</code> item was not applying consistently when the item was placed in the <strong>Amulet (necklace)</strong> slot.</p>

<h3>Fixed</h3>
<ul>
<li>The Curios compatibility layer now properly delegates <code>curioTick</code>, <code>onEquip</code>, <code>onUnequip</code>, <code>onStateChange</code>, <code>canEquip</code>, <code>canUnequip</code>, and other <code>ICurioItem</code> methods to the actual Curios API implementations from third-party mods.</li>
<li>The new <code>RegaliaCurioAdapter</code> correctly bridges <code>top.theillusivec4.curios.api.type.capability.ICurioItem</code> → <code>com.skd.regaliaslotsapi.api.type.capability.ICurio</code>, ensuring active effects (like Jump Boost) work identically to the real Curios mod.</li>
</ul>

<h3>Internal</h3>
<ul>
<li>Renamed all compatibility layer classes from <code>Curios*</code> to <code>Regalia*</code> (e.g., <code>CuriosTypeBridge</code> → <code>RegaliaTypeBridge</code>, <code>CuriosCompatMod</code> → <code>RegaliaCompatMod</code>, etc.) for consistent naming within the Regalia Slots API codebase. The <code>top.theillusivec4.curios.api</code> package (copied Curios API for binary compatibility) remains unchanged.</li>
</ul>

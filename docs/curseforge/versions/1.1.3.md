<h2>v1.1.3 - Complete the third-party curio ticking fix</h2>

<p>The <strong>Supersalto II (Jump Boost II)</strong> fix shipped in 1.1.1 for Reliquary's <code>angelic_faher</code> was incomplete. The effect still flickered and cut out when the amulet was worn, most noticeably on a dedicated server.</p>

<p>1.1.1 wired its <code>RegaliaCurioAdapter</code> only into the Curios-facing capability (<code>curios:item</code>, registered by <code>RegaliaCompatMod</code>). But the native tick loop in <code>RegaliaSlotsApiCommonEvents.tick</code> resolves curios through <code>RegaliaSlotsApiCapability.ITEM</code>, which never consulted items registered through the copied Curios API (the <code>RegaliaExtensionsAdapter.REGISTERED_ITEMS</code> map). For third-party items such as Reliquary's amulet, <code>RegaliaSlotsApi.getCurio(stack)</code> returned empty, so <code>curioTick</code>, <code>onEquip</code>, and <code>onUnequip</code> were never called from the native loop.</p>

<h3>Fixed</h3>
<ul>
<li>The native <code>RegaliaSlotsApiCapability.ITEM</code> provider now also resolves items registered through the Curios API, wrapping them in <code>RegaliaCurioAdapter</code>.</li>
<li>The native tick loop gained a fallback: when no native curio resolves for a slotted stack, it queries the stack's <code>curios:item</code> capability and adapts it through the new <code>CuriosICurioAdapter</code> (<code>top.theillusivec4.curios.api.type.capability.ICurio</code> &rarr; <code>com.skd.regaliaslotsapi.api.type.capability.ICurio</code>), so active tick effects run every server tick and the equip/unequip lifecycle fires correctly.</li>
</ul>
